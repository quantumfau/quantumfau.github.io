Workshop lesson: Quantum from Zero to One

Two tracks, one team

You don’t have to code to compete

Every team should have both a Domain/Industry Expert and a Builder/Developer Expert. The two roles are equal, and the best projects come from them working on one problem together.

Domain/Industry Expert · coding optional

Bring the problem

You bring a field you know, like finance, logistics, health, policy, or operations, and make sure the team is solving a problem that really exists. You frame it, judge whether a quantum approach fits, and tell the story. No Python install needed.

Builder/Developer Expert · Python + Qiskit

Build and run it

You write the Qiskit code, run the circuits, and measure the quantum result next to a classical baseline. You need Python. You don’t need a physics background.

Read the full guide to both tracks

The goal

You are not expected to prove quantum beats classical. Define a meaningful problem, try an appropriate quantum approach, compare it with a classical method when you can, and explain what you learned, including the limitations. A strong project is one of:

  • A mapped problem: a real industry problem turned into something a quantum computer can work on, run small
  • A benchmark: the same problem run classically and quantumly at small scale
  • A tool: something that makes quantum work easier, like a visualizer or teaching aid
  • An analysis: a sourced assessment of where quantum does or doesn’t fit in a sector
Judging

Projects are reviewed on technical execution, problem framing and relevance, honesty about limitations, and presentation. The full rubric and weights are still to come.

Claiming a quantum method beat classical computing without the comparison written down is outside this event.

How to submit

Each team submits its project on DeepStation by Sunday, Oct 18 at 11:00 AM. Every team has to be registered on DeepStation. Your submission needs:

  • README.md and your notebooks or source code
  • USE-CASE.md: the problem, the industry, and why it matters
  • Slides or a demo video, plus requirements.txt if there’s code
  • LIMITATIONS.md is strongly encouraged
Accounts & security
  • Everyone uses their own IBM Quantum account. No shared logins.
  • Never paste your IBM API key or a password in chat, a shared screen, or code you commit to GitHub.
  • The free Open Plan gives up to 10 minutes of real quantum hardware time per 28 days. Build and test on a simulator, then run on hardware once.
Good to know
  • Everything is free: Qiskit, the IBM Quantum Open Plan, and GitHub.
  • Loaner laptops aren’t confirmed. A Chromebook works, since everything can run in the browser.
  • Old tutorials using quantum-computing.ibm.com or channel="ibm_quantum" are out of date. Use the handbook.
  • Code of conduct: coming soon. Questions or accessibility needs? Email an FAU organizer.
